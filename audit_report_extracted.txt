PROJECT AUDIT REPORT: AI-POWERED DECISION INTELLIGENCE PLATFORM FOR SMES
Audit Date: November 2026Repository: InsightIQ--AI-mainAudit Scope: Complete codebase inspection (Architecture, Frontend, Backend, Database, CSV Pipelines, AI/ML Services, Security, Deployment)Execution Mode: Strict read-only verification (no files modified, created, or deleted).
A. Executive Summary
This codebase is NOT a dataset upload and analysis tool. There is no CSV/dataset upload pipeline, no machine learning model, and no external Large Language Model (LLM) API integration anywhere in the project.
Instead, what has actually been built is a full-stack multi-tenant SME Enterprise Resource Planning (ERP) and Business Intelligence (BI) Dashboard:
Frontend: A modern, single-page React 19 application configured with Tailwind CSS, Recharts, and React Router v7. It implements an ERP UI with modules for Sales, Inventory, Customers, Expenses, Analytics, Reports, Company Profile, Settings, and an AI chat assistant.
Backend: A modular Python FastAPI backend (/api/v1) with 14 endpoint groups, JWT authentication, bcrypt password hashing, and role-based access control.
Database: A relational schema implemented with SQLAlchemy ORM and Alembic migrations targeting PostgreSQL (13 relational tables), accompanied by a database seeding script (seed.py).
"AI" & Decision Intelligence Reality: 
The "AI Insights" are generated via deterministic SQL heuristics and static threshold rules (e.g., if revenue growth exceeds 5%, an insight record is created with a hardcoded 94.50 confidence score).
The "AI Assistant" chat is a client-side JavaScript regex/keyword matcher executing in the browser (sendAIMessage in api.js). It queries summary numbers from the backend KPI endpoint and injects them into pre-written response templates.
CSV Reality: 
CSV Upload does not exist anywhere in the code. There is no <input type="file">, no file upload parser (e.g., PapaParse), no backend file handling route (UploadFile), and no Pandas data processing.
The only CSV functionality is CSV Export (downloading in-memory table records as .csv files using client-side Blob generation).

E. Frontend Audit
Architecture & Routing
The frontend is structured around React Router v7 (BrowserRouter) with code-splitting via React.lazy and Suspense with an animated PageLoader. All application routes except /, /login, /signup, and /forgot-password are guarded by a ProtectedRoute component that verifies JWT existence in localStorage.
Real Operations vs. Mock Interactions
Forms with Genuine CRUD: 
Signup.jsx: Posts to /api/v1/auth/register, creating real records in the database.
Login.jsx: Posts to /api/v1/auth/login, validates credentials, stores token, and navigates.
Customers.jsx: Modal form performs actual HTTP POST to /api/v1/customers and DELETE to /api/v1/customers/{id}.
Sales.jsx: Form reads live customer and product lists to populate dropdowns, calculating line totals and executing POST /api/v1/sales.
Inventory.jsx: "Add Product" creates both a product row and an inventory row via POST /api/v1/products?initial_stock=.... "Adjust Stock" executes PUT /api/v1/inventory/{id}.
Expenses.jsx: Form executes POST /api/v1/expenses and DELETE /api/v1/expenses/{id}.
Reports.jsx: "Create Report" modal executes POST /api/v1/reports.
Profile.jsx: "Save Preferences" executes PUT /api/v1/users/me.
Forms/Buttons that are Pure UI or Mocked: 
ForgotPassword.jsx: Clicking "Send Reset Link" runs an 800ms setTimeout and toggles a success message with no network activity.
Settings.jsx: "Save Preferences" serializes toggles into browser localStorage (insightiq_workspace_settings); it never contacts any backend server.
Profile.jsx "Revoke Device": Filters an in-memory array in component state; no session revocation endpoint exists.
Reports.jsx "View Report" modal: Displays hardcoded metadata cards rather than rendered document contents.
Charts & Visualization Data Sources: 
Dashboard.jsx: Area chart for revenue and donut chart for expenses are populated from real backend API calls (/dashboard/overview).
Analytics.jsx: The primary monthly revenue trend and expense breakdown are live from /analytics/overview. However, the secondary tabs ("Customer Growth", "Performance Radar", and "Quarterly Comparison") fall back to hardcoded arrays in src/data/mockAnalytics.js with simulated network delays (delay(300)).
Error & Loading Handling: 
Error boundaries wrap both the top-level route tree and individual protected layouts (ErrorBoundary.jsx).
Skeletons and shimmer animations are displayed during loading states.
Axios interceptors catch HTTP 401 errors, purge local credentials, and dispatch an auth:unauthorized window event that redirects the user to /login.

G. Database Audit
Direct Answers to Required Database Questions:
Is a database actually configured?Yes. PostgreSQL is explicitly configured using SQLAlchemy 2.0 with the Psycopg 3 driver in database.py and config.py.
Is there a database connection implementation?Yes. create_engine with pool_pre_ping=True and a get_db() session generator are implemented in database.py.
Are any tables defined?Yes, exactly 13 relational tables are defined in code and backed by an Alembic migration: 
companies
users
employees
customers
products
inventory
sales
sale_items
expenses
business_metrics
reports
ai_insights
ai_recommendations
Is the application actually saving user data?Yes. When running connected to PostgreSQL, user signups, profile changes, products, sales, inventory adjustments, customers, expenses, and generated insights are written to PostgreSQL tables via SQLAlchemy db.add() and db.commit().
Where are users, datasets, uploaded files, and analysis results stored? 
Users: users table in PostgreSQL.
Datasets / Uploaded files: Nowhere. File uploads do not exist in the architecture.
Analysis results: Stored in the ai_insights and ai_recommendations tables in PostgreSQL.
Does the data persist after refreshing/restarting the application? 
When connected to PostgreSQL: Yes, all committed rows persist.
When running in frontend-only/demo mode: Data changes only persist within localStorage for authentication and settings; other mock lists reset on reload.
Is PostgreSQL being used, or was it only part of the original plan?PostgreSQL is actively implemented in the backend code and is not just a plan. However, it is not currently running as an embedded or active service, and there is no .env file present in the repo to supply the connection string.
